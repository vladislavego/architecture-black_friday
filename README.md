# scaling

Проект демонстрирует финальную реализацию шардирования, репликации и кеширования MongoDB,
а также работу приложения с шардированным кластером.

База данных: `somedb`  
Коллекция: `helloDoc`

---

## Реализовано

- MongoDB Cluster с двумя шардами
- Репликация каждого шарда (Replica Set из 3 узлов)
- Replica Set для Config Server (3 узла)
- `mongos` как единая точка входа в MongoDB Cluster
- Распределение данных по шардам
- Кеширование запросов с использованием Redis

---

## Архитектура

В проекте используются следующие компоненты:

- `configSrv` — сервер конфигурации MongoDB (Replica Set из 3 узлов)
- `shard1` — шард MongoDB (Replica Set из 3 узлов)
- `shard2` — шард MongoDB (Replica Set из 3 узлов)
- `mongos` — роутер MongoDB
- `redis` — in-memory кеш для ускорения чтения данных
- `pymongo_api` — приложение, подключающееся к MongoDB через `mongos`

Каждый шард развёрнут в виде Replica Set, что обеспечивает отказоустойчивость и автоматический выбор primary-узла.  
Все клиентские запросы к базе данных выполняются исключительно через `mongos`.  
Redis используется для кеширования данных на уровне приложения.

Итоговая архитектурная схема проекта находится в файле `scaling.drawio` в корне репозитория.

## Быстрый старт

Для запуска финальной версии проекта необходимо перейти в директорию
`sharding-repl-cache`

```shell
    cd sharding-repl-cache
```

и выполнить команды
```shell
    docker compose up -d
    ./scripts/mongo-init.sh
```

Более подробная инструкция по запуску, проверке MongoDB, репликации и
кеширования описана в файле README.md внутри директории `sharding-repl-cache`.
