# mongo-sharding-repl

Проект демонстрирует реализацию шардирования и репликации MongoDB,
а также работу приложения с шардированным кластером.

В рамках задания реализованы:

- MongoDB Cluster с двумя шардами
- репликация каждого шарда (по 3 реплики)
- mongos как единая точка входа в кластер
- распределение данных по шардам
- кеширование запросов с использованием Redis
- приложение, работающее с MongoDB через mongos

База данных: somedb  
Коллекция: helloDoc

---

## Архитектура

В проекте используются следующие компоненты:

- configSrv — сервер конфигурации MongoDB с реплика-сетом из 3 узлов
- shard1 — шард MongoDB с реплика-сетом из 3 узлов
- shard2 — шард MongoDB с реплика-сетом из 3 узлов
- mongos — роутер MongoDB
- redis — in-memory кеш для ускорения чтения данных
- pymongo_api — приложение, подключающееся к MongoDB через mongos

Каждый шард развёрнут в виде Replica Set, что обеспечивает отказоустойчивость
и возможность автоматического выбора primary-узла.

Redis используется для кеширования данных на уровне приложения.

Все клиентские запросы к базе данных выполняются исключительно через mongos.

## Как запустить

### 1. Запуск сервисов

```shell
    docker compose up -d
```

Проверьте, что все контейнеры успешно запущены:

```shell
    docker compose ps
```

---

### 2. Инициализация шардирования

Для инициализации MongoDB используется скрипт `mongo-init.sh`.

Скрипт выполняет:

- инициализацию сервера конфигурации (Replica Set)
- инициализацию реплика-сета shard1 (3 узла)
- инициализацию реплика-сета shard2 (3 узла)
- регистрацию шардов в mongos
- включение шардирования для базы somedb
- настройку шардирования коллекции helloDoc
- наполнение базы тестовыми данными

Запуск скрипта:

```shell
    ./scripts/mongo-init.sh
```

## Как проверить

### Проверка через приложение

Если проект запущен локально, откройте в браузере:

    http://localhost:8080

Ожидаемый результат:

- статус OK
- тип топологии Sharded
- общее количество документов ≥ 1000
- отображаются оба шарда

---

### Если вы запускаете проект на виртуальной машине

Узнать белый ip виртуальной машины

```shell
curl --silent http://ifconfig.me
```

Откройте в браузере http://<ip виртуальной машины>:8080

### Доступные эндпоинты

Список доступных эндпоинтов, swagger http://<ip виртуальной машины>:8080/docs

### Проверка распределения данных по шардам

Shard1:

```shell
    docker-compose exec -it shard1-1 mongosh --port 27018
    use somedb
    db.helloDoc.countDocuments()
    exit()
```

Shard2:

```shell
    docker-compose exec -it shard2-1 mongosh --port 27019
    use somedb
    db.helloDoc.countDocuments()
    exit()
```

---

### Проверка репликации

Проверка состояния реплик shard1:

```shell
    docker-compose exec -T shard1-1 mongosh --port 27018 
    rs.status().members.forEach(m => print(m.name + " | " + m.stateStr))
```

Проверка состояния реплик shard2:

```shell
    docker-compose exec -T shard2-1 mongosh --port 27019
    rs.status().members.forEach(m => print(m.name + " | " + m.stateStr))
```

---

### Проверка кеширования

Кеширование работает для эндпоинта:

    /helloDoc/users

Первый запрос выполняется с обращением к MongoDB и занимает больше времени.
Повторные запросы выполняются из Redis-кеша и занимают менее 100 мс.

Пример проверки для локального запуска:

```shell
curl -w "\nTime: %{time_total}s\n" -o /dev/null -s http://localhost:8080/helloDoc/users
curl -w "\nTime: %{time_total}s\n" -o /dev/null -s http://localhost:8080/helloDoc/users
```
